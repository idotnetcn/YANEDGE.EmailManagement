# 3. 产品设计原则

## 3.1 业务工作台优先

本系统不是传统个人邮箱客户端的简单复刻，产品设计应以“企业业务工作台”为核心，而不是仅围绕“收件箱”展开。
页面布局、操作入口、状态展示都应服务于“处理任务、完成协同、沉淀业务”这一目标。

## 3.2 线程优先而不是单封邮件优先

邮件在企业场景下往往需要按会话上下文处理，因此产品上应优先突出：

- 线程视图
- 上下文查看
- 当前处理状态
- 当前负责人
- 关联业务对象

单封邮件仍然需要存在，但不应成为协同的唯一中心。

## 3.3 共享邮箱协同优先

对于 `sales@`、`support@`、`purchase@`、`finance@` 等共享邮箱，必须支持：

- 自动分派
- 人工认领
- 转派
- 内部备注
- 审批
- 处理状态流转

避免“大家都看得到，但没人负责”的协同失效问题。

## 3.4 内外信息分离

系统中必须清晰区分两类内容：

1. **对外邮件内容**：发给外部客户、供应商、合作方的正式邮件内容
2. **内部协同内容**：备注、审批意见、处理记录、提醒等内部信息

内部信息绝不能误发给外部对象。

## 3.5 业务关联优先

邮件处理不应脱离业务上下文，因此产品设计上应支持用户在邮件处理过程中快速看到：

- 对应客户
- 对应联系人
- 对应订单 / 合同 / 工单
- 最近关联记录
- 历史往来邮件

## 3.6 安全与审计前置

涉及邮件查看、附件下载、外发、审批、规则配置、模板发布等动作，产品层面应预留：

- 权限校验入口
- 审计记录点
- 操作确认机制
- 风险提示机制

# 6. 工作台功能设计

## 6.1 页面定位

工作台是当前用户登录后的默认入口，目标是以最短路径把用户带到“当前最重要的事项”。

## 6.2 页面模块

### 6.2.1 我的待办
展示当前用户待处理的事项，包括：

- 待认领线程
- 待处理线程
- 待审批邮件
- 被 @ 提醒的协同事项
- 发件失败待处理任务

### 6.2.2 我的未读
展示当前用户可见范围内的未读邮件或未读线程统计，支持快速跳转。

### 6.2.3 待审批邮件
展示当前用户作为审批人的待审批项，包括：

- 邮件主题
- 发件邮箱
- 发起人
- 提交时间
- 审批状态
- 是否包含附件
- 快速审批入口

### 6.2.4 发件失败告警
展示发件失败任务，支持：

- 查看失败原因
- 重试
- 取消
- 联系管理员

### 6.2.5 最近协同动态
展示近期与当前用户相关的协同事件：

- 新分派给我
- 某线程被转派
- 某审批已通过 / 已拒绝
- 某线程新增内部备注

### 6.2.6 今日统计
展示与当前用户或当前组织相关的基础指标：

- 今日收件量
- 今日发件量
- 今日已处理线程数
- 待办数量
- 超时数量

## 6.3 快捷操作

工作台需提供快捷入口：

- 写邮件
- 打开共享邮箱
- 查看待审批
- 查看发件失败
- 打开我的待办
- 查看我负责的线程

## 6.4 交互要求

- 工作台卡片支持点击跳转明细页
- 数字统计支持快速过滤
- 告警卡片需明显标示风险等级
- 待办卡片按优先级、时间排序展示

# 7. 邮件中心功能设计

## 7.1 收件箱

### 7.1.1 页面目标
用于查看当前用户可见范围内的邮件或线程，并完成基础处理操作。

### 7.1.2 列表展示字段建议
- 主题
- 发件人
- 邮箱账号
- 是否未读
- 是否星标
- 是否有附件
- 标签
- 处理状态
- 当前负责人
- 业务对象摘要
- 收件时间 / 最新时间

### 7.1.3 筛选条件建议
- 关键词
- 发件人
- 邮箱账号
- 文件夹类型
- 是否未读
- 是否星标
- 是否有附件
- 标签
- 处理状态
- 审批状态
- 业务对象类型
- 时间范围

### 7.1.4 支持操作
- 查看详情
- 标记已读 / 未读
- 星标 / 取消星标
- 打标签
- 分派 / 转派 / 认领
- 回复
- 转发
- 归档
- 删除
- 下载附件
- 批量操作

## 7.2 已发送

### 7.2.1 页面目标
查看已发出的邮件及其状态、回执、关联业务信息。

### 7.2.2 展示重点
- 发件主题
- 收件人
- 发件邮箱
- 发件时间
- 发件状态
- 是否审批通过
- 业务对象关联
- 是否有附件

### 7.2.3 支持操作
- 查看详情
- 再次编辑发送
- 转发
- 查看审批记录
- 查看发件任务日志
- 归档

## 7.3 草稿箱

### 7.3.1 页面目标
管理未发送的邮件草稿。

### 7.3.2 展示重点
- 草稿主题
- 创建人
- 最后编辑时间
- 发件邮箱
- 是否缺少收件人
- 是否待审批

### 7.3.3 支持操作
- 编辑草稿
- 删除草稿
- 提交审批
- 立即发送
- 定时发送

## 7.4 归档箱

### 7.4.1 页面目标
查看已完成处理并进入归档状态的邮件 / 线程。

### 7.4.2 特点
- 默认只读
- 支持查看历史上下文
- 支持导出
- 支持恢复（视权限而定）

## 7.5 垃圾箱

### 7.5.1 页面目标
管理已删除但未彻底清除的邮件。

### 7.5.2 支持操作
- 查看
- 恢复
- 彻底删除（高权限）
- 查看删除原因与删除人

## 7.6 共享邮箱

### 7.6.1 页面目标
用于从“邮箱池”维度查看共享邮箱中的线程和处理状态。

### 7.6.2 页面结构建议
- 左侧：共享邮箱切换
- 中部：线程列表
- 右侧：详情 / 处理信息

### 7.6.3 展示信息
- 线程主题
- 最近来信人
- 当前状态
- 当前负责人
- 处理时长
- SLA 风险提示
- 是否包含附件
- 是否有业务对象关联

### 7.6.4 支持操作
- 认领
- 退回共享池
- 批量分派
- 查看处理记录
- 查看线程上下文
- 回复 / 转发
- 归档

## 7.7 星标邮件

展示用户标记为重要的邮件，支持快速访问与取消星标。

## 7.8 我负责的线程

只展示当前用户为负责人或当前处理人的线程，用于快速聚焦自己的工作内容。

## 7.9 我参与的线程

展示用户作为历史处理人、评论人、审批人、抄送接收人等参与过的线程。

## 7.10 全部线程

面向高权限用户，用于查看指定范围内全部线程，适合管理者和管理员使用。

# 8. 协同处理功能设计

## 8.1 分派记录

### 8.1.1 页面目标
查看线程或邮件的责任流转历史。

### 8.1.2 展示内容
- 分派时间
- 分派人
- 接收人 / 接收角色 / 接收组织
- 分派类型（分派 / 转派 / 认领 / 退回）
- 当前状态
- 备注

### 8.1.3 支持操作
- 查看详情
- 导出记录
- 对当前待处理项继续转派

## 8.2 内部备注

### 8.2.1 页面目标
记录协同处理过程中的内部信息，不对外发送。

### 8.2.2 备注内容
- 处理建议
- 风险提示
- 补充说明
- @某人提醒
- 约定后续动作

### 8.2.3 规则要求
- 内部备注不可进入对外邮件正文
- 支持按时间线查看
- 支持编辑权限控制
- 支持删除审计

## 8.3 审批中心

### 8.3.1 页面目标
管理外发邮件审批流程。

### 8.3.2 页面分区建议
- 我的待审批
- 我发起的审批
- 已审批记录
- 被拒绝记录

### 8.3.3 展示信息
- 邮件主题
- 发件人
- 发件邮箱
- 收件人
- 是否含敏感附件
- 审批发起时间
- 当前状态
- 节点信息

### 8.3.4 支持操作
- 审批通过
- 审批拒绝
- 查看正文和附件
- 查看业务对象关联
- 填写审批意见
- 批量审批（可选）

## 8.4 待办管理

### 8.4.1 页面目标
统一展示需要用户处理的线程、审批、提醒等事项。

### 8.4.2 待办类型
- 新分派
- 待认领
- 待处理
- 待回复
- 待审批
- 发件失败待确认
- 规则异常待处理

## 8.5 协同日志

# 16. 核心业务流程设计

## 16.1 邮件同步流程

```text
系统读取启用同步的邮箱
→ 创建同步任务
→ 连接 IMAP / Provider
→ 拉取增量邮件
→ 解析头信息、正文、附件、收件人
→ 进行线程归并
→ 写入邮件与附件数据
→ 执行规则引擎
→ 自动匹配联系人和业务对象
→ 更新同步任务结果
→ 如有异常则记录失败日志
```

## 16.2 收件处理流程

```text
邮件进入系统
→ 出现在共享邮箱池 / 用户收件箱
→ 自动分派或人工认领
→ 查看详情与上下文
→ 补充内部备注
→ 关联业务对象
→ 回复 / 转派 / 审批
→ 处理完成
→ 归档
```

## 16.3 写邮件与发件流程

```text
用户进入写邮件页面
→ 选择发件邮箱
→ 选择模板 / 签名
→ 填写收件人、正文、附件
→ 校验收件人与权限
→ 判断是否需要审批
→ 若无需审批则直接创建发件任务
→ 若需审批则提交审批
→ 审批通过后进入后台发件队列
→ 更新发送结果
→ 触发回调与审计记录
```

## 16.4 共享邮箱协同流程

```text
共享邮箱收到新邮件
→ 命中自动分派规则 / 进入共享池
→ 某用户认领
→ 用户处理中
→ 添加内部备注
→ 转派给其他人 / 申请审批
→ 回复外部
→ 完成处理
→ 归档线程
```

## 16.5 审批流程

```text
用户提交待审批邮件
→ 系统创建审批单
→ 审批人查看正文、附件、关联对象
→ 审批通过 / 审批拒绝
→ 通过则允许发送
→ 拒绝则退回修改或终止
```

## 16.6 业务关联流程

```text
邮件入库
→ 匹配联系人邮箱
→ 识别订单号 / 合同号 / 工单号
→ 自动建立关联
→ 用户人工修正
→ 外部系统可补写映射
```

## 16.7 附件访问流程

```text
用户点击附件
→ 系统校验邮件可见权限
→ 校验附件访问权限
→ 若允许则预览 / 下载
→ 写访问审计日志
→ 返回文件内容
```

# 17. 状态模型设计

## 17.1 线程处理状态

| 状态 | 说明 | 可流转到 |
|---|---|---|
| 待分派 | 新进入共享池，尚未有负责人 | 待处理、处理中、已关闭 |
| 待处理 | 已明确负责人，但未开始处理 | 处理中、待审批、已完成 |
| 处理中 | 正在处理 | 待审批、已完成、已关闭 |
| 待审批 | 当前需审批后继续 | 处理中、已完成、已关闭 |
| 已完成 | 已完成处理 | 已归档 |
| 已归档 | 已归档留存 | 可恢复（高权限） |
| 已关闭 | 不再继续处理 | 一般不再流转 |

## 17.2 审批状态

| 状态 | 说明 |
|---|---|
| 不需要审批 | 普通邮件 |
| 待审批 | 已提交审批 |
| 审批通过 | 可继续发送 |
| 审批拒绝 | 不允许发出 |
| 已撤回 | 发起人撤回 |

## 17.3 发件任务状态

| 状态 | 说明 |
|---|---|
| 待发送 | 已创建待发任务 |
| 发送中 | 正在发送 |
| 成功 | 已成功发送 |
| 失败 | 发送失败 |
| 已取消 | 已取消发送 |

## 17.4 同步任务状态

| 状态 | 说明 |
|---|---|
| 待执行 | 尚未开始 |
| 执行中 | 正在同步 |
| 成功 | 同步完成 |
| 部分成功 | 有部分邮件失败 |
| 失败 | 整体失败 |

## 17.5 用户阅读状态

| 状态 | 说明 |
|---|---|
| 未读 | 用户未查看 |
| 已读 | 用户已查看 |
| 星标 | 用户标记重要 |
| 已归档 | 用户个人归档 |
| 已隐藏 | 用户个人隐藏 |

5. 线程区：历史上下文
6. 协同区：分派、备注、待办、审批记录

- 批量已读

- 批量分派
- 批量归档
- 批量删除

## 18.5 风险提示交互要求

- 邮件详情展示尽量减少页面跳转

## 21.2 一致性要求

- 状态命名统一
- 按钮文案统一
- 列表交互风格统一
- 审批、分派、归档等动作在各页面保持一致体验

## 21.3 可追溯性要求

- 所有协同行为可在时间线中追踪
- 状态变更有来源
- 审批操作有意见记录
- 附件下载有日志

## 21.4 可扩展性要求

- 菜单可扩展
- 业务对象类型可扩展
- 规则动作可扩展
- 模板变量来源可扩展
- 统计维度可扩展

---

# 22. 结论

邮件管理系统在产品功能设计上，应围绕以下五个核心能力展开：

1. **线程化处理**
2. **共享邮箱协同**
3. **业务对象关联**
4. **模板规则驱动**
5. **开放集成与审计可追溯**

本系统的页面与交互不应仅参考传统邮箱客户端，而应更接近“企业业务协同工作台”。
一期应优先保证核心收发、协同、关联、审批、审计、集成能力可落地，在此基础上逐步增强搜索、统计、SLA、智能化等能力。

该文档可作为后续原型设计、研发拆解、测试设计和交付评审的直接依据。
